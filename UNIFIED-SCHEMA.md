# Unified Graph Schema

## The Problem

Three systems, three graphs:

| System | Graph ID | Node Labels | Write Pattern |
|--------|----------|-------------|---------------|
| private-lab | default | Worker, WorkerVersion, Run, Studio, Experiment, Finding, Pool, Venue | CREATE with edge |
| finalbuilds2 | finalbuilds | Idea, Hypothesis, Experiment, Product, Site, Strategy, BuildRun, Capability | CREATE with _GENESIS |
| workerkit | SQLite fallback | (separate) | SQLite |

**Only 2 labels overlap: Experiment, Capability.** They have different properties.

## The Fix: Unified Schema

One graph ID. One set of labels. All systems write to it.

### Unified Node Labels

```yaml
# Core entities (shared across all systems)
Worker:
  props: [id, name, current_version_id, letta_agent_id, metadata]
  
WorkerVersion:
  props: [version_id, worker_id, parent_version_id, agent_runtime, model_provider, model_name, skill_versions, source]

Run:
  props: [id, studio_id, task_instance_id, split, worker_id, worker_version_id, outcome, score, cost_usd, started_at, completed_at]

Experiment:
  props: [id, name, hypothesis_id, status, cohort_assignment, started_at, completed_at]

Hypothesis:
  props: [id, statement, status, confidence, mechanism, cites_evidence, predictions]

Finding:
  props: [id, subject, predicate, object, confidence, source_snapshot_id, evidence_tier]

# Commerce entities (z2m + finalbuilds2)
Product:
  props: [id, name, category, score, market, status]

Site:
  props: [id, name, url, platform, country, status]

Idea:
  props: [id, name, generator_id, hypothesis_parents, status]

Capability:
  props: [id, name, subdomains]

# Bittensor entities (private-lab)
Pool:
  props: [pool_id, name, subdomains]

Venue:
  props: [venue_id, name, protocol]
```

### Unified Relationships

```yaml
# Worker lineage
Worker -[:HAS_VERSION]-> WorkerVersion
WorkerVersion -[:RAN]-> Run

# Experiment tracking
Experiment -[:TESTS]-> Hypothesis
Experiment -[:HAS_ARM]-> ExperimentArm
Run -[:PART_OF]-> Experiment

# Commerce flow
Idea -[:PRODUCED]-> Product
Product -[:EXPOSES]-> Site
Product -[:GENERATED_BY]-> IdeaGenerator

# Evidence chain
Finding -[:SUPPORTED_BY]-> Experiment
Finding -[:DERIVED_FROM]-> Hypothesis

# Cross-system links
Run -[:PRODUCED]-> Finding
Finding -[:FEEDS]-> Hypothesis  # z2m finding → finalbuilds2 hypothesis
Experiment -[:USES]-> Capability
```

### Unified Graph ID

All systems must use the same graph ID:

```
HYDRA_GRAPH_ID=unified
```

### Implementation

1. Set `HYDRA_GRAPH_ID=unified` in all configs
2. Add missing labels to private-lab: Product, Site, Idea, Hypothesis, Strategy
3. Add missing labels to finalbuilds2: Worker, WorkerVersion, Run, Finding, Pool, Venue
4. Shared properties for overlapping labels (Experiment, Capability)
5. Cross-reference queries

### Query Examples

```cypher
// Find all products generated by ideas that support active hypotheses
MATCH (i:Idea)-[:PRODUCED]->(p:Product)
WHERE i.status = 'validated'
RETURN p.name, p.score

// Find all runs that contributed findings to a hypothesis
MATCH (r:Run)-[:PRODUCED]->(f:Finding)-[:DERIVED_FROM]->(h:Hypothesis)
WHERE h.id = 'H7_ai_gifting'
RETURN r.id, r.score, f.subject

// Find all workers that ran experiments testing a hypothesis
MATCH (w:Worker)-[:HAS_VERSION]->(wv)-[:RAN]->(r:Run)-[:PART_OF]->(e:Experiment)-[:TESTS]->(h:Hypothesis)
WHERE h.id = 'H1_personalization_arbitrage'
RETURN w.name, r.score

// Cross-system: commerce opportunity → security finding
MATCH (p:Product)-[:EXPOSES]->(s:Site)
WHERE s.country = 'NO'
MATCH (f:Finding)-[:AFFECTS]->(p)
RETURN p.name, s.url, f.subject
```

### Migration Steps

1. Stop all three systems
2. Export existing data from each graph
3. Set `HYDRA_GRAPH_ID=unified` in all configs
4. Re-import with unified labels
5. Add cross-reference edges
6. Restart all systems
7. Verify queries work across systems
