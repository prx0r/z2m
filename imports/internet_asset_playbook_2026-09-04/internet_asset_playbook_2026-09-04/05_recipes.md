# 5. Repeatable recipes

These are templates to transpose across markets. The objective is to reuse the engine while changing the dataset and transaction.

## Recipe A — The “verified directory”

### Use when

A market has lots of providers but weak trust.

### Dataset

- provider identity;
- location;
- price band;
- certifications;
- supported products/services;
- last verified date;
- evidence URL;
- response time;
- user-supplied outcome data.

### Pages

- provider profile;
- category comparison;
- location + category;
- requirement + provider;
- “verified this month” feed.

### Monetization

1. free basic profile;
2. paid verified profile;
3. category sponsorship;
4. lead fee;
5. paid data export / alerts.

### Moat

Verification history.

### Best examples to study

TrustMRR, G2-style review databases, regulated/provider registries.

## Recipe B — The “meta-directory”

### Use when

People already use many niche directories/marketplaces and need a map of the maps.

### Dataset

- directory/site;
- niche;
- audience;
- geography;
- pricing;
- submission rules;
- freshness;
- traffic/authority proxies;
- whether listings are free/paid.

### Monetization

- sponsored slots;
- paid listing upgrades;
- newsletter;
- submission service;
- buyer/referral fee.

### Proven analogue

JobBoardSearch.

### Critical twist

The user must need to compare directories. A generic “AI tools directory of AI tools directories” is not enough.

## Recipe C — The “quote desk”

### Use when

The transaction is expensive and the buyer is confused.

### Good categories

- commercial equipment;
- installers;
- specialist B2B services;
- security/compliance vendors;
- managed IT;
- premium home projects.

### UX

1. user answers 6–10 questions;
2. engine explains tradeoffs;
3. shortlist of 3–5 matching suppliers;
4. optional “get quotes” action;
5. suppliers receive structured lead.

### Monetization

- per lead;
- per qualified call;
- exclusive territory sponsorship;
- supplier subscription.

### Why AI helps

The decision tree and explanation can feel like expert consulting while the underlying data remains structured and auditable.

## Recipe D — The “comparison matrix”

### Use when

Buyers already search “X vs Y”, “best X for Y”, “alternative to X”.

### Dataset

- features;
- public pricing;
- integrations;
- limits;
- security/compliance;
- user segment;
- contract terms;
- affiliate availability;
- last verified date.

### Monetization

- affiliate;
- sponsor placements clearly labelled;
- premium buyer report;
- vendor leads.

### Important

Never let affiliate payout decide the score. Separate editorial score from monetization and disclose relationships.

### Proven analogue

Tooltester; large-scale SaaS comparison sites.

## Recipe F — The “price / availability monitor”

### Use when

Price and availability vary over time.

### Product

- current table;
- price history;
- change alerts;
- region/currency normalization;
- supplier reliability;
- “best current deal” decision layer.

### Monetization

- affiliate;
- sponsored offers;
- premium alerts;
- data/API subscription.

### Why it survives AI Search

## Recipe H — The “Q4 gift matcher”

### Use when

Buyer intent is emotional, time-sensitive, and conversion happens quickly.

### Dataset

- gift type;
- recipient;
- personalization options;
- delivery cutoff;
- destination country;
- production time;
- price;
- review count/rating where licensed/allowed;
- whether digital/physical;
- return policy.

### UX

“Who is it for? Budget? Need it by when? Personalised? Funny/sentimental/luxury?” -> shortlist.

### Monetization

- affiliate;
- featured makers;
- direct own-brand personalized products;
- email reminder/retargeting.

### Why this fits your existing Q4 work

It turns the same personalized-gift thesis into a demand-capture asset rather than relying only on paid ads or a single storefront.

## Recipe I — AISec provider/evidence directory

### Dataset

- standards supported;
- public test/evidence links;
- deployment modes;
- UK/EU relevance;
- pricing model;

### Monetization

- consulting funnel;
- premium buyer brief;
- API/data access.

### Strategic advantage

## Recipe J — Bittensor subnet operator intelligence

### Dataset

- subnet;
- task/miner interface;
- registration cost;
- active miner count;
- emissions;
- reward concentration;
- hardware/API requirements;
- code links;
- benchmark/evaluation method;
- profitability history;
- last verified block/time.

### Monetization

- premium alerts;
- “entry pack”/starter kit;
- data API;
- sponsor infrastructure providers;
- paid analyst report.

### Critical requirement

This only works if data is genuinely on-chain/current and the site can explain **how to act**, not merely restate subnet descriptions.
