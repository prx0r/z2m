# Validation protocol: kill weak ideas quickly

## Gate 0 — exclusions
Reject if:
- core demand depends on bug bounty payouts or speculative prizes;
- core model is dropshipping/reselling physical goods;
- requires covert access, bypassing access controls, credential theft or ToS-hostile automation;
- requires high-stakes automated medical/legal/financial decisions;
- cannot identify a lawful, durable data source.

## Gate 1 — economic event
The product must connect to at least one:
- revenue won;
- labor hours removed;
- loss/error prevented;
- deadline/obligation satisfied;
- infrastructure complexity reduced.

If the user only says “cool” or “interesting,” reject.

## Gate 2 — frequency
Score highest when the event occurs daily/weekly/monthly. A one-time task can still work, but price it per transaction rather than forcing subscription.

## Gate 3 — artifact test
Ask prospects to show the actual object:
- file;
- spreadsheet;
- portal;
- email;
- current script;
- screenshot;
- output they manually create.

If nobody can produce an artifact, the pain is probably too vague.

## Gate 4 — willingness-to-pay proxy
Calculate current manual cost:

`monthly pain cost = occurrences × minutes per occurrence ÷ 60 × fully-loaded hourly cost`

A strong tool can often charge 10–30% of conservative savings, or more if it creates revenue/avoids risk.

## Gate 5 — distribution wedge
You need one channel before coding:
- exact high-intent search query;
- incumbent app ecosystem;
- trade/industry community;
- consultant/agency channel;
- association directory;
- integration marketplace;
- public dataset that creates shareable pages;
- workflow-native extension.

“No idea, launch on Product Hunt” = fail.

## Gate 6 — 48-hour concierge test
Before automation, manually perform the job for 3 prospects:
- charge at least one;
- record input/output;
- record corrections;
- record time saved;
- find the repeating structure.

## Gate 7 — product boundary
A good first product is usually:

`one user + one input + one job + one output + one delivery channel`

Examples:
- one accountant + Stripe statement PDF + normalize + Xero CSV + email;
- one contractor + public tender feed + qualify + alert + Slack;
- one n8n operator + broken workflow + diagnose + patch proposal + n8n API.

## Evidence scoring used by the engine

- verified revenue demand: 18%
- workflow pain/criticality: 12%
- willingness to pay: 10%
- recurrence: 10%
- build simplicity: 10%
- data/API access: 8%
- distribution wedge: 10%
- localization/verticalization: 7%
- gross-margin potential: 5%
- competition gap: 10%
- minus platform risk/support/regulatory burden penalties.

A score is not proof. It is a **queue ordering mechanism** for interviews and concierge tests.
