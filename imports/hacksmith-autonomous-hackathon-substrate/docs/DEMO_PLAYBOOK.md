# Demo Playbook

A demo is causal proof, not a tour. Current Devpost guidance recommends a screencast showing the project functioning and an elevator pitch in the opening seconds.

Default 2:30 choreography:
- 0:00–0:12 hook
- 0:12–0:28 before-state
- 0:28–1:35 live workflow
- 1:35–1:55 evidence/receipt
- 1:55–2:15 sponsor depth
- 2:15–2:30 product/startup close

Show real input, sponsor response/state, meaningful decision/gate, final verified outcome and concise provenance.

Do not spend the short video on exhaustive features, literature, code scrolling, setup, every model/provider, generic TAM or speculative roadmap.

**Invariant:** sponsor appears before the consequence attributed to it.

**Public demo safety:** a Run button must not silently make billable/destructive writes. Stop at explicit approval, use a safe sandbox, or label fixture/recorded execution clearly.
