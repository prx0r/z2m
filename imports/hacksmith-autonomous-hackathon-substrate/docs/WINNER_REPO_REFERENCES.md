# Concrete Winner Repository References

These are not visual templates to copy. They are evidence for recurring presentation structure.

## DispatchAI — UC Berkeley AI Hackathon grand prize
Repository: https://github.com/DispatcherAI/DispatcherAI

Useful pattern:
- one-line product definition immediately
- visible award/build-time proof
- demo near the top
- TL;DR answers What / Why / How fast / Result
- one end-to-end scenario in the demo: inbound call -> AI handling -> structured operator cockpit
- live links and open artifacts grouped together

Substrate takeaway: a technically deep project can still make the first screen extremely legible. Put the scenario and proof before implementation detail.

## HackMate — 1st overall, GDG Mac-a-Thon 2025
Repository: https://github.com/owengretzinger/hackmate

Useful pattern:
- explicit problem and solution before feature detail
- demo prominent in README
- architecture after judges understand the value
- quickstart and next steps separated cleanly

Substrate takeaway: the repository itself is part of judging/persuasion; information architecture matters.

## Ctrl+Meet — 1st place, Amazon internal hackathon
Repository: https://github.com/kcitlyn/ctrl-meet

Useful pattern:
- outcome and judging context immediately visible
- demo above fold
- concrete validated problem statistics
- explicit explanation of what the author would want a technical judge to inspect
- engineering tradeoffs, security and tests documented as proof rather than generic claims
- prior art credited honestly rather than straw-manned

Substrate takeaway: strong technical submissions make skeptical questions easy to answer and distinguish measured proof from marketing.

## FireForm — 1st place, Reboot the Earth
Repository: https://github.com/fireform-core/fireform-pitch

Useful pattern:
- story follows one concrete incident rather than a feature list
- pitch ends directly in the live product
- minimal self-contained presentation surface

Substrate takeaway: one user story can carry the entire pitch into the live demo with almost no conceptual context switching.

## Generalized winner pattern

`memorable problem -> one concrete scenario -> functioning product -> technical proof -> sponsor/architecture depth -> future wedge`

Avoid cargo-culting award badges, giant diagrams or visual themes. The transferable advantage is **proof sequencing**.
