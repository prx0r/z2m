# Deadline Runbook

The exact hours depend on event length. The ratios are more important.

## First 10% — rules + thesis
Do not code immediately. Resolve rules/rubric and choose a sponsor-causal idea that can produce one memorable demo transformation.

## Next 45% — real core
Build only the end-to-end path. Sponsor adapter, state/evidence, decision/policy, safe action boundary, receipt. Keep UI thin.

## Next 20% — hardening
Clean checkout, CI, failure cases, secret hygiene, mutable-state revalidation, idempotency, API version, provenance.

## Next 15% — judge surfaces
Landing page, README, PITCH, live demo choreography. Delete/archive distracting development artifacts.

## Final 10% — record and submit
Script from actual UI. Dry run. Record. Upload early enough to process. Fill Devpost. Test every link incognito. Submit. Freeze.

## Under severe deadline pressure
Priority order:
1. eligibility/submission blockers
2. public CI green
3. safe truthful live demo
4. sponsor causality
5. script/video
6. Devpost submission
7. README cleanup
8. extra polish
9. optional features never outrank the above
