# Architecture Synthesis — MW + Z2M + FinalBuilds2

## Canonical split

```text
MW / Oracle        = WHAT CAN MAKE MONEY?
Z2M                = WHAT COMMERCE/PRODUCT THESES LOOK GOOD?
FinalBuilds2       = WHAT SHOULD WE BUILD/TEST NEXT?
Hermes / WorkerKit = DO THE WORK
Hydra + R2         = WHAT ACTUALLY HAPPENED?
```

Do not create another autonomous orchestration framework inside Z2M.

The shared canonical object should be `EconomicOpportunity`. MW contributes economic surfaces, actionability/H-level and change detection. Z2M contributes commerce sensors, product economics, geo/seasonal hypotheses and offer design. FinalBuilds2 owns admission, capacity, experiment definition, verified building, telemetry, attribution and promotion.

## Capital ladder

### Treasury = $0
Admit only:
- zero/minimal irreversible spend;
- H0/H1 preferred;
- strong external verifier;
- high existing-capability match;
- reusable asset exhaust.

### Treasury = $10–$100
Add:
- digital products;
- POD/personalization;
- affiliate specialist sites;
- marketplace listings;
- free Merchant Center feeds;
- tiny paid validation only where break-even math clears.

### Treasury = $100–$500
Add:
- supplier samples;
- small Google Shopping tests;
- selected physical bundles;
- country-specific specialist stores.

Revenue from lower-capital lanes should fund higher-capital experiments.

## Existing FinalBuilds assets to reuse

- domain intelligence

- budget
- email-arb
- x402

- MCP/REST surfaces

Before a builder creates a new component, the planner should query existing capabilities.

## Security prerequisite

The public `mw` repository contains historical plaintext credential material in a handover file. Rotate exposed credentials and remove secret material from history before expanding autonomous execution. Never include those values in reports, prompts, logs or Hydra.
